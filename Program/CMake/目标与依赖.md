# CMake 目标与依赖

> 现代 CMake 的核心思想：以「目标（target）」为中心，用 `target_*` 命令管理属性和依赖。

## 什么是目标（Target）

由 `add_executable()` 或 `add_library()` 创建的东西就是一个目标。围绕它设置属性，而不是用全局变量。

```cmake
add_executable(app main.cpp)
add_library(mylib STATIC mylib.cpp)
```

## 链接库

```cmake
target_link_libraries(app PRIVATE mylib)
```

## PUBLIC / PRIVATE / INTERFACE

这是现代 CMake 最关键的概念，决定属性是否「传递」给使用者：

| 关键字 | 自己用 | 传递给依赖者 | 场景 |
|--------|:----:|:----:|------|
| `PRIVATE` | ✅ | ❌ | 仅内部实现需要 |
| `PUBLIC` | ✅ | ✅ | 自己和使用者都需要 |
| `INTERFACE` | ❌ | ✅ | 仅使用者需要（如纯头文件库） |

例子：

```cmake
target_include_directories(mylib
    PUBLIC  include      # 用 mylib 的人也能看到 include
    PRIVATE src          # 只有 mylib 自己编译时用
)

target_link_libraries(mylib
    PUBLIC  fmt::fmt     # 头文件暴露了 fmt，使用者也需要
    PRIVATE zlib         # 只在实现里用到
)
```

## 编译选项与宏定义

```cmake
target_compile_definitions(app PRIVATE DEBUG_MODE=1)  # 定义宏
target_compile_options(app PRIVATE -Wall -Wextra)     # 编译选项
target_compile_features(app PRIVATE cxx_std_17)       # 语言特性
```

## 查找并使用外部库

```cmake
find_package(fmt REQUIRED)             # 查找依赖，找不到就报错
target_link_libraries(app PRIVATE fmt::fmt)
```

- `REQUIRED`：找不到直接报错终止。
- 现代库通常提供 `命名空间::目标` 形式（如 `fmt::fmt`），直接链接即可自动带上头文件路径。

## 多目录项目

顶层 CMakeLists.txt：
```cmake
add_subdirectory(src)
add_subdirectory(lib)
```

子目录里各自写自己的 CMakeLists.txt，定义自己的目标。

## 拉取第三方依赖（FetchContent）

无需手动安装，构建时自动下载：

```cmake
include(FetchContent)
FetchContent_Declare(
    fmt
    GIT_REPOSITORY https://github.com/fmtlib/fmt.git
    GIT_TAG        10.2.1
)
FetchContent_MakeAvailable(fmt)

target_link_libraries(app PRIVATE fmt::fmt)
```
